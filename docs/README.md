# chaierww 文档

本目录的 Markdown 会被应用内「设置 → Wiki 文档」**自动收录**：新增或修改文件后刷新页面即可看到，
不需要改前端，也没有第二份目录清单要同步。

## 这是什么

chaierww 是一个**只在本机运行**的多账号切换工具。你在官方客户端里正常登录账号，
它负责把登录态保存下来，之后在需要的时候把某个账号的登录态换回去。

- 没有我们自己的服务器，没有云端中转，断网也能切号
- 账号必须是你自己的，不提供共享、租借或代登录
- 凭据由系统 DPAPI 绑定当前 Windows 用户加密，密钥不落磁盘

非官方第三方工具，与 WorkBuddy / Trae 及其权利人无隶属、授权或背书关系。
使用前请读 **[免责声明](./policies/DISCLAIMER.md)**。

## 界面入口怎么走

侧栏只放高频业务（概览 / 号池 / 用量 / 网关 / 活动）。低频运维项收在**左下角的设置按钮**里，
进入设置后再用左侧分类切换。

| 入口 | 位置 | 说明 |
|:--|:--|:--|
| 设置 | 左下角设置按钮，或 `/settings` | 一个 `shell` 沉浸页：左栏是设置分类 |
| 接口文档 | 设置 → 接口文档，或 `/settings?tab=api` | 同源 iframe 内嵌 `/docs` 的 Swagger UI |
| Wiki 文档 | 设置 → Wiki 文档，或 `/settings?tab=wiki` | 就是本目录的 Markdown |
| 运行日志 | 设置 → 运行日志，或 `/settings?tab=logs` | 按级别 / 文件 / 关键字检索，出参已脱敏 |

设置页不是弹窗：它是一条独立路由，刷新与分享都成立。切分类只改 `?tab=`，浏览器后退栈不会被塞满。

## 数据放在哪

默认在 `~/.chaierww/`，可以用环境变量 `CHAIERWW_HOME` 改到别处。整个目录拷走就是完整迁移。

```
chaierww.db    账号表、凭据表、备份表、切换任务表
backups/       备份点，每个都有 sha256 清单
logs/          按天切分的运行日志（写日志前已脱敏）
avatars/       账号头像
webview/       网页版登录态快照（只在本机有效，不进导出包）
```

安装包与数据目录是分开的：覆盖安装不碰 `~/.chaierww`，**卸载也不会删它**。
要彻底清干净，卸载后手动删除该目录。

## 三条文档链路，各自只有一个真源

| 内容 | 真源 | 为什么不会过期 |
|:--|:--|:--|
| 接口文档 | 应用自己的路由定义 | Swagger 直接读运行中的 `/api/openapi.json`，加接口自动出现 |
| Wiki | 本目录的 `.md` | 目录接口在每次请求时扫盘，标题取首个 `# ` 行 |
| 日志 | `~/.chaierww/logs/*.log` | 直接读文件，不经过第二层落库 |

接口文档不走 CDN：Swagger UI 的 JS/CSS 打包在 `src/chaierww/webassets/swagger/`，
离线或内网也能打开。用 `CHAIERWW_DISABLE_DOCS=1` 可以整体关掉，
此时设置页会显示明确原因而不是套一层空白 iframe。

本机 API 没有鉴权（只监听 127.0.0.1），所以 Swagger 不声明 `securitySchemes`。
将来若引入访问令牌，必须同时补 `securitySchemes` 与 `security`，否则文档只能看不能调。

## 几个容易误解的点

**切换前为什么要退出客户端。**
客户端运行时会持续改写登录态文件。在它写文件的过程中做备份，备份下来的可能是半截状态，
失败回滚时反而会写回坏数据。所以顺序是「确认退出 → 备份 → 写入」，不是「备份 → 等它退出」。

**为什么导入账号拿不到昵称。**
客户端把昵称一起加密了。解密需要复刻它的密钥派生流程，那是协议级风险。
所以凭据被整份按不透明数据保存，显示名退化为 `用户 <uin>`，你可以自己改备注。

**读不到为什么不是 0。**
统计类指标在数据缺失时返回 `null` 而不是 0，界面上也显示为未知。
把「没读到」显示成「0」会让人误判成额度用完了。

**日志里为什么看不到完整 token。**
出参前统一跑正则脱敏：`Bearer xxx` 打成 `Bearer ***`，`token= / password= / secret=`
的值也打码。要排查问题看结构就够，不需要明文。
